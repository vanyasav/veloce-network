# Бэкапы и восстановление

## Что бэкапится

Только Postgres-база Directus (`~/directus-cms/`) — она содержит всю
структуру данных (рестораны, меню, пользователей, права). Сами файлы
(`directus_uploads` volume — фото блюд/лого) **не бэкапятся отдельно**
на сегодня — это отдельный docker volume на том же VPS, если диск
пропадёт, пропадут и он, и бэкапы БД (см. ограничение ниже).

## Как настроено

- Скрипт: `~/scripts/backup-directus.sh`
- Cron: ежедневно в **03:30** (`crontab -l` на VPS, чтобы проверить)
- Куда: `~/backups/directus-<YYYYMMDD-HHMMSS>.sql.gz`
- Хранение: **14 дней**, старее — автоматически удаляется
  (`find ... -mtime +14 -delete`)
- Лог: `~/backups/backup.log`

```bash
docker exec directus-cms-database-1 pg_dump -U directus directus | gzip > "$FILE"
```

## Восстановление

```bash
ssh vpnmain
gunzip -c ~/backups/directus-YYYYMMDD-HHMMSS.sql.gz | \
  docker exec -i directus-cms-database-1 psql -U directus directus
```

**Внимание**: это восстановит поверх текущей БД (не пересоздаёт с
нуля) — если нужно чистое восстановление, сначала пересоздать БД/volume
Postgres (`docker compose down -v` для стека `directus-cms` **уничтожит
данные**, использовать только осознанно перед восстановлением из
бэкапа).

## Известное ограничение — единая точка отказа

Бэкапы лежат **на том же VPS**, что и сама база. Если пропадёт диск
сервера (сбой, случайное удаление, компрометация) — пропадут
одновременно и рабочие данные, и все 14 дней бэкапов. Это приемлемо
для стадии "нет платящих клиентов", но **до первого реального клиента
стоит перенести бэкапы в объектное хранилище** (Cloudflare R2 или
Backblaze B2 — копейки за такой объём). Не сделано за эту сессию —
следующий шаг.

Черновой план на будущее: после `pg_dump` в скрипте добавить `aws s3
cp`/`rclone copy` в R2-бакет с отдельными учётными данными (не путать
с Cloudflare Pages API-токеном — для R2 нужен отдельный access key).

## Что НЕ покрыто бэкапами вообще

- Сама конфигурация VPS (Caddyfile, docker-compose файлы, cron) — не
  версионируется в git на сегодня, live только на сервере. Что-то
  дублируется здесь в docs/ как справочник, но это не замена
  восстановлению — при полной потере VPS всю инфраструктуру придётся
  разворачивать заново по этим документам вручную
- Файлы в Directus (фото) — см. выше
- Astro-шаблон — **исходники есть локально** и не только на VPS, это
  единственная часть системы, которая уже не является единой точкой
  отказа
