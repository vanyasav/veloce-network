# Бизнес-стратегия

## Идея

В Италии много ресторанов/пиццерий без нормального сайта. Продавать
готовые сайты на Claude Code (написание) + переиспользуемый шаблон.
Ниша живая (реальный незакрытый спрос), но конкурентная (агентства,
Wix/Squarespace, фрилансеры) — дифференциация через скорость сборки,
многоязычность под туристов и внимание к локальному SEO/Google Business
Profile, а не только "сайт как артефакт".

## Почему Astro, а не Angular

Изначальная идея — использовать Angular (владелец им пользуется). Решили
не использовать по следующим причинам:

- **SEO** критичен для локального бизнеса, а Angular SPA рендерится на
  клиенте — без Angular Universal (SSR) Google видит пустой div. Astro
  по умолчанию рендерит статический HTML, ноль JS если не запрошено явно
  (islands architecture)
- **Вес/скорость** — Angular-бандл даже минимальный это сотни KB JS,
  бьёт по Core Web Vitals, которые Google учитывает при ранжировании
- **Сопровождение** — контент (меню, часы) меняется редко, Angular
  избыточен для такого профиля обновлений
- Astro не поддерживает Angular-компоненты напрямую (только
  React/Preact/Svelte/Vue/Solid/Lit внутри "островков"), но поскольку
  сайты пишутся через Claude Code, а не руками — кривая обучения
  синтаксису некритична

Итог: один переиспользуемый Astro-шаблон + Tailwind, генерируемый под
каждого клиента подстановкой данных, а не переписыванием кода.

## Бизнес-модель

**Recurring revenue вместо разовой продажи.** Разовая продажа сайта —
разовый чек и разовый поиск клиентов каждый месяц. Подписка
(хостинг+поддержка, ~€25-90/мес в зависимости от тарифа) даёт
пассивный доход поверх новых продаж. Setup fee разово (€400-1000) +
retainer помесячно/по году.

Что включено в подписку: хостинг (Cloudflare Pages — почти бесплатно),
обновление контента, домен/SSL/email, бэкапы, редкий созвон. Смягчение
churn — годовая предоплата, ежеквартальный отчёт с метриками
(просмотры, переходы в WhatsApp), домен/email в комплекте (барьер на
уход).

**Google Business Profile — не опция.** Для локального общепита
большинство "открытий" идёт через Google Maps/Search, не через сайт
напрямую. Продавать пакетом: сайт + настройка GBP (фото, категория,
атрибуты, ответы на отзывы) + интеграция с TheFork/Glovo/WhatsApp — сайт
как часть видимости в интернете, а не единственный продукт.

**Мультиязычность обязательна** (турпоток) — минимум IT+EN, в
туристических зонах +DE/FR. Диетические пометки (vegan/vegetarian/
gluten-free/allergens) как отличие от конкурентов — уже реализовано в
схеме Directus.

**Self-service редактирование** — чтобы не стать бесплатной техподдержкой
на каждую правку цены. Решено через собственный Directus (см.
[directus-cms.md](./directus-cms.md)), а не через сторонние SaaS.

## Путь принятия решений по инфраструктуре

1. Начали с идеи Decap CMS (git-based, бесплатно) — но узнав, что у
   владельца есть свой VPS, пересмотрели в пользу мультитенантного
   self-hosted решения (Directus) — один бэкенд на всех клиентов вместо
   одного репозитория на клиента
2. Directus выбран над Strapi/Payload из-за декларативной модели прав на
   уровне строк (`restaurant_id = $CURRENT_USER.restaurant`) — критично
   для изоляции данных между арендаторами без риска багов в самописном
   access-control коде
3. Разделение: CMS (Directus) — на своём VPS (контроль), сами живые
   сайты клиентов — на Cloudflare Pages (не завязаны на аптайм VPS)

## GTM (следующие шаги, не начаты)

- Сделать 2-3 сайта бесплатно/за копейки знакомым заведениям — портфолио
  + отзывы + обкатка шаблона на реальных данных
  Продавать через демонстрацию визуала, не технологий
- Когда появится первый реальный клиент: кастомный домен, реальные фото/
  меню, договор на подписку

## Открытый вопрос про домен

VPS уже использует домен `veloce-network.xyz` для существующего
VPN-сервиса (см. [infrastructure.md](./infrastructure.md)) — поддомен
`panel.veloce-network.xyz` используется под админку CMS, это нормально
для внутреннего инструмента. Для клиентских сайтов "Veloce Network" как
бренд, вероятно, не подходит (ассоциация с VPN) — стоит выбрать отдельный
бренд/домен под сам сервис создания сайтов, когда дело дойдёт до продаж.
